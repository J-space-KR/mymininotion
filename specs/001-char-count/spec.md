# Feature Specification: 글 내용 글자 수 표시

**Feature Branch**: `001-char-count`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "내용입력칸 아래에다가 내용을 입력하면 글자 수 계산하는 기능을 만들거야"

## Clarifications

### Session 2026-10-06

- Q: 글자 수를 공백 포함 하나만 보여줄까, 공백 제외도 같이 보여줄까? → A: 둘 다 보여준다. 헷갈리지 않게 각각 "공백 포함 N자", "공백 제외 N자"로 이름을 붙여 표시한다.
- Q: 공백 포함 글자 수에서 줄바꿈(Enter) 한 번을 몇 자로 셀까? → A: 널리 쓰이는 글자 수 세기 도구(네이버 글자수 세기 등)의 기준을 따라 1자로 센다. 공백 제외에서는 띄어쓰기와 함께 뺀다. 운영체제에 따라 줄바꿈이 두 문자(CR+LF)로 들어와도 1자로 센다.
- Q: 목표 글자 수(분량 맞추기) 기능을 넣을까? → A: 넣는다 (사용자: "제대로 된 글자 수 세기 프로그램을 갖고 싶다"). 목표를 적으면 "공백 포함 1,234 / 5,000자"처럼 진행 상황을 보여주고, 넘으면 색이 바뀌며 몇 자 넘었는지 알려준다. 목표는 비워 둘 수 있고, 최대값을 막지 않는다. 쓸 수 있는 내용 길이에도 제한이 없다.
- Q: 목표 글자 수를 글마다 따로 정하고 저장할까? → A: 사용 흐름은 두 가지다. ① 목표 없이 그냥 써서 공백 포함·공백 제외 글자 수를 본다. ② 목표 글자 수를 먼저 정해 두고, 그 목표에 맞춰 내용을 쓴다. 목표는 글마다 따로 정하고 저장해서, 다시 열어도 남아 있다.
- Q: 목표 글자 수와 비교할 숫자는 공백 포함과 공백 제외 중 무엇인가? → A: 둘 다. 목표 하나를 공백 포함·공백 제외 두 숫자 각각과 비교해 진행 상황과 초과 여부를 따로 보여준다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내용을 쓰면서 글자 수 확인하기 (Priority: P1)

글 상세 화면에서 내용을 쓰는 사용자는, 내용 입력칸 바로 아래에서 지금까지 쓴 글자 수를
"공백 포함 N자"와 "공백 제외 N자" 두 가지로 본다. 글자를 입력하거나 지우면 두 숫자가 바로 바뀐다. 따로 버튼을 누르거나 저장할 필요가 없다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 이것만 있어도 "글자 수 제한이 있는 글"(지원서,
소개글 등)을 미니 노션에서 쓰고 길이를 맞출 수 있다.

**Independent Test**: 글 상세 화면을 열고 내용 입력칸에 글자를 입력·삭제하면서, 아래에 표시된
숫자가 입력한 글자 수와 같은지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 내용이 비어 있는 글의 상세 화면, **When** 화면이 열리면, **Then** 내용 입력칸 아래에 "공백 포함 0자", "공백 제외 0자"가 표시된다.
2. **Given** 내용이 비어 있는 글, **When** "안녕 하세요"를 입력하면, **Then** "공백 포함 6자", "공백 제외 5자"가 표시된다.
3. **Given** 내용이 "안녕 하세요"인 글, **When** 마지막 글자 하나를 지우면, **Then** "공백 포함 5자", "공백 제외 4자"가 표시된다.
4. **Given** 내용이 비어 있는 글, **When** 여러 줄짜리 글을 한 번에 붙여넣으면, **Then** 붙여넣은 직후 두 글자 수가 모두 갱신된다.
5. **Given** 내용 입력칸이 비어 있는 글, **When** 제목만 입력하면, **Then** 두 글자 수 모두 0 그대로다 (제목은 세지 않음).

---

### User Story 2 - 다시 열었을 때 바로 글자 수 보기 (Priority: P2)

이미 내용이 있는 글을 목록에서 다시 열면, 아무것도 입력하지 않아도 저장된 내용의 글자 수가
처음부터 표시된다.

**Why this priority**: 글을 여러 번에 나눠 쓰는 경우가 많다. 다시 열 때마다 한 글자를 쳐야 숫자가
나온다면 기능이 반쪽짜리가 된다. 다만 P1이 있어야 의미가 있어서 두 번째다.

**Independent Test**: 내용이 저장된 글을 만들어 두고, 목록에서 그 글을 열었을 때 입력 없이 올바른
글자 수가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 내용이 "할 일 정리"로 저장된 글, **When** 목록에서 그 글을 열면, **Then** 입력하지 않아도 "공백 포함 6자", "공백 제외 4자"가 표시된다.

---

### User Story 3 - 화면을 보지 않고도 글자 수 알기 (Priority: P3)

화면 읽기 프로그램(스크린 리더)을 쓰는 사용자도 글자 수 표시를 읽을 수 있고, 그것이 "글자 수"라는
것을 알 수 있다.

**Why this priority**: 누구나 쓸 수 있게 하는 기본 배려다. 혼자 쓰는 도구라 우선순위는 낮지만,
처음 만들 때 넣는 비용이 가장 적다.

**Independent Test**: 스크린 리더(또는 접근성 트리 확인 도구)로 글 상세 화면을 읽었을 때 글자 수
표시가 "글자 수"라는 이름과 숫자로 읽히는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 글 상세 화면, **When** 스크린 리더가 내용 입력칸 아래 영역을 읽으면, **Then** "공백 포함"·"공백 제외"라는 이름과 각각의 숫자가 함께 읽힌다.
2. **Given** 사용자가 글자를 입력하는 중, **When** 숫자가 바뀌어도, **Then** 스크린 리더가 매 글자마다 숫자를 읽어 입력을 방해하지 않는다.

---

### User Story 4 - 목표 글자 수에 맞춰 쓰기 (Priority: P2)

지원서처럼 분량이 정해진 글을 쓰는 사용자는 내용을 쓰기 전에(또는 쓰는 중에) 그 글의 목표 글자 수(예: 5,000자)를 정해 둔다. 그러면 지금 몇 자를
썼고 목표까지 얼마나 남았는지 보이고, 목표를 넘으면 바로 알 수 있다.

**Why this priority**: "제대로 된 글자 수 세기 프로그램"의 핵심이다. 숫자만 보여주면 목표와 비교하는 계산을
사용자가 직접 해야 한다. P1(글자 수 표시) 위에 얹는 기능이라 두 번째다.

**Independent Test**: 목표를 적고 내용을 목표 아래·같음·위로 바꿔 가며, 진행 표시와 초과 알림이 맞게
나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 목표가 비어 있는 글, **When** 화면을 보면, **Then** 지금처럼 글자 수만 보이고 진행 표시는 없다.
2. **Given** 목표 5,000자, 내용이 공백 포함 1,234자·공백 제외 1,050자, **When** 화면을 보면, **Then** "공백 포함 1,234 / 5,000자", "공백 제외 1,050 / 5,000자"가 함께 보인다.
3. **Given** 목표 10자, 내용 "가나다라마 바사아자"(공백 포함 10자, 공백 제외 9자), **When** 화면을 보면, **Then** 두 숫자 모두 초과가 아니다 (같으면 초과 아님).
4. **Given** 3번 상태, **When** 끝에 공백 하나를 더 입력하면, **Then** 공백 포함만 "1자 초과"로 바뀌고, 공백 제외(9자)는 초과가 아니다.
5. **Given** 3번 상태, **When** 끝에 "차차"를 더 입력하면, **Then** 공백 포함 "2자 초과", 공백 제외 "1자 초과"가 각각 보인다.
6. **Given** 목표를 넘은 상태, **When** 글자를 지워 목표 이하가 되면, **Then** 해당 숫자의 초과 표시가 바로 사라진다.
7. **Given** 목표를 5,000자로 정한 글, **When** 목록으로 나갔다가 다시 열면, **Then** 목표 5,000자가 그대로 남아 있다.
8. **Given** 글 A의 목표가 1,000자, **When** 다른 글 B를 열면, **Then** 글 B에는 글 A의 목표가 보이지 않는다 (글마다 따로).
9. **Given** 목표가 있는 글, **When** 목표 칸을 비우면, **Then** 진행·초과 표시가 사라지고 다시 열어도 목표가 없다.

---

### Edge Cases

- 내용이 공백·줄바꿈만으로 되어 있으면? → 공백 포함은 공백과 줄바꿈을 각각 1자로 센다 (예: 공백 2개 + 줄바꿈 1개 = 3). 공백 제외는 0이다.
- 이모지(예: 👍, 👨‍👩‍👧)나 결합 문자가 있으면? → 화면에 보이는 한 글자를 1자로 센다.
- 한글을 조합하는 중(예: "ㅎ" → "하" → "한")이면? → 입력칸에 지금 보이는 그대로 센다. 조합 중에도 숫자는 1을 넘지 않는다.
- 다른 곳에서 복사한 글에 줄바꿈이 두 문자(CR+LF)로 들어 있으면? → 줄바꿈 1번으로 보고 공백 포함 1자로 센다.
- 아주 긴 내용(예: 10만 자)을 붙여넣으면? → 입력이 눈에 띄게 느려지지 않고 숫자가 맞게 표시된다.
- 목표 칸에 0, 음수, 소수, 숫자가 아닌 글자를 넣으면? → 1 이상의 정수만 목표로 인정한다. 그 밖의 값은 목표가 없는 것으로 보고, 이유를 짧게 안내한다.
- 목표를 아주 크게(예: 1,000,000자) 적으면? → 막지 않고 그대로 목표로 쓴다.
- 글자 수가 1,000 이상이면? → 세 자리마다 쉼표를 넣어 읽기 쉽게 표시한다 (예: 1,234).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 글 상세 화면의 내용 입력칸 바로 아래에 내용의 글자 수를 표시해야 한다.
- **FR-002**: 글자 수는 내용 입력칸의 글자만 센다. 제목은 세지 않는다.
- **FR-003**: 시스템은 글자 수를 두 가지로 함께 표시한다.
  - **공백 포함**: 모든 글자를 센다. 띄어쓰기·탭은 각각 1자, 줄바꿈 1번도 1자다
    (줄바꿈이 두 문자로 들어와도 1자).
  - **공백 제외**: 띄어쓰기·탭·줄바꿈 같은 빈칸 문자를 모두 빼고 센다.
- **FR-004**: 화면에 한 글자로 보이는 문자(한글 완성형, 이모지, 결합 문자 등)는 1자로 센다.
- **FR-005**: 내용을 입력·삭제·붙여넣기·잘라내기 하면 별도 동작 없이 즉시 글자 수가 갱신되어야 한다.
- **FR-006**: 글 상세 화면을 처음 열 때, 저장된 내용의 글자 수가 입력 없이 바로 표시되어야 한다.
- **FR-007**: 두 숫자는 헷갈리지 않게 각각 이름을 붙여 "공백 포함 N자", "공백 제외 N자" 형태로 표시하고, 1,000 이상이면 세 자리 쉼표를 넣는다 (예: "공백 포함 1,234자 · 공백 제외 1,050자").
- **FR-008**: 글자 수 표시는 스크린 리더로 읽을 수 있어야 하고, 입력할 때마다 소리로 끼어들지 않아야 한다.
- **FR-009**: 글자 수 표시는 보조 정보이므로 본문보다 눈에 덜 띄어야 하고, 글쓰기를 방해하지 않아야 한다.
- **FR-010**: 이 기능은 글의 제목·내용 저장 방식을 바꾸지 않는다. 글자 수 자체는 저장하지 않는다 (목표 글자 수만 저장).
- **FR-011**: 사용자는 목표 글자 수를 1 이상의 정수로 적거나 비워 둘 수 있다. 최대값은 제한하지 않는다.
- **FR-012**: 목표가 있으면 목표 하나를 공백 포함·공백 제외 두 숫자 **각각**과 비교해 "공백 포함 현재 / 목표자", "공백 제외 현재 / 목표자" 형태로 보여준다 (세 자리 쉼표 포함).
- **FR-013**: 두 숫자 각각에 대해, 현재 글자 수가 목표보다 **크면** 그 숫자만 초과 상태로 표시한다. 눈에 띄는 색으로 바꾸고 "N자 초과"를 함께 보여준다. 색만으로 구분하지 않는다. 목표와 같으면 초과가 아니다.
- **FR-014**: 내용을 고쳐 목표 이하가 되면 해당 숫자의 초과 표시가 즉시 사라진다.
- **FR-015**: 내용 입력 길이 자체에는 제한을 두지 않는다. 목표를 넘어도 계속 쓸 수 있다.
- **FR-016**: 목표 글자 수는 글마다 따로 저장되고, 글을 다시 열거나 새로고침해도 유지된다. 목표를 비우면 "목표 없음"으로 저장된다.
- **FR-017**: 목표 글자 수 저장은 기존 글 저장 흐름(자동 저장)을 따른다. 목표가 없던 기존 글은 "목표 없음"으로 열린다.

### Key Entities

- **글(Page)**: 이미 있는 데이터. 제목과 내용을 가진다. 이 기능은 글의 **내용**을 읽어 글자 수를 센다.
  - 새 속성 **목표 글자 수**: 1 이상의 정수 또는 "없음". 글마다 하나. 기존 글은 "없음".

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 내용을 입력하거나 지운 뒤 사용자가 기다림을 느끼지 않을 만큼 즉시(체감 0.1초 이내) 글자 수가 바뀐다.
- **SC-002**: 엣지 케이스에 적힌 예시를 포함한 검증용 문장 모두에서, 표시된 두 글자 수(공백 포함·공백 제외)가 손으로 센 값과 100% 일치한다.
- **SC-006**: 사용자가 설명 없이 두 숫자 중 어느 것이 공백 포함이고 어느 것이 공백 제외인지 바로 구분한다.
- **SC-003**: 10만 자 내용에서도 한 글자를 입력할 때 입력이 끊기거나 늦게 보이는 현상이 없다.
- **SC-004**: 사용자가 글 상세 화면을 열고 3초 안에, 따로 찾지 않아도 글자 수 표시를 발견한다.
- **SC-007**: 목표가 있을 때, 사용자가 계산 없이 3초 안에 "목표까지 남았는지, 넘었는지"를 말할 수 있다.
- **SC-005**: 기존 기능(제목·내용 입력, 자동 저장, 삭제)의 동작이 이 기능 추가 전과 똑같다.

## Assumptions

- 이 기능은 `02-prd.md`의 기능 목록(W-1~W-5)에 없는 **추가 기능**이다. W-4(제목·내용 입력) 화면에
  붙는 보조 기능으로 보고, PRD의 "첫 버전에 넣지 않는 것"에 해당하지 않는다. 강의 실습(Day40)용으로
  하네스 흐름을 익히는 것이 목적이다.
- 바이트 수, 단어 수는 이번 범위가 아니다.
- 줄바꿈 1자 규칙은 널리 쓰이는 글자 수 세기 도구의 일반 기준을 따른 것이다. 일부 사이트처럼 줄바꿈을
  2자로 세거나 바이트로 세는 방식은 따르지 않는다.
- 목표 글자 수는 알려주는 용도일 뿐이다. 목표를 넘어도 입력을 막거나 저장을 막지 않는다.
- 글자 수는 화면에서 매번 계산하며, 저장하거나 목록 화면에 보여주지 않는다.
- 외부 통신(API·DB)이 필요 없는 기능이다. 목표 글자 수는 지금의 글 저장 방식(기존 저장소)에 함께 저장된다.
  나중에 Supabase로 옮길 때 글 표에 목표 글자 수 칸이 하나 필요하다.
- 표시 위치·색·크기와 문구는 `DESIGN.md`의 보조 텍스트 규칙과 문구 톤을 따른다.
